# 遊戲設計

只寫已經確定的事。還沒決定的放在最後的「未定事項」。

## 已確定
- 概念：兩位玩家合力操控一隻龍做料理
- 3D 遊戲，畫面以 3D 模型呈現
- 合作遊戲（玩家一起合作達成目標）
- 2 名玩家，在同一台裝置上本地合作
- 操作：每位玩家各用一支麥克風，主要以聲音操作遊戲
- 非對稱合作：兩位玩家負責不同的操作行為
  - 玩家 A：控制龍的移動。用聲音大小決定龍停在哪個高度：
    - 大聲：最高點
    - 中音量：中間高度
    - 小聲：最低高度
    - 沒出聲：停在最後的高度，不會改變
    - 校正：遊戲開始時，以當下測到的音量作為校正基準
  - 玩家 B：控制龍的吸與吐。遊戲辨識玩家 B 發出的字音：
    - 「吸」：吸收、收集食材
    - 「吐」：噴火，燒掉食材
- 核心玩法：龍在三層之間上下飛，吸取從左邊過來的食材，放進右邊的鍋子當材料
- 場景分層：目前做三層（高、中、低），之後可能增加層數。龍在三層之間上下飛，玩家 A 的三段音量各對應一層
- 層數和「音量對應哪一層」都做成可調整的設定，增加層數時改設定就能調整音量分段
- 龍只會上下移動，不會左右或前後移動
- 鏡頭：攝影機面向龍頭
- 兩位玩家共用同一個畫面（不分割畫面）
- 畫面配置：每一層由左到右依序是「食材 → 龍 → 鍋子」。龍在畫面中間，面向左邊的食材。食材不斷從畫面左側外面出現，往右邊的龍前進
- 食材：人類、精靈、矮人、史萊姆、獸人、蝙蝠
- 食材隊伍：
  - 每一層的食材從左往右移動，排隊出現，走到最右邊就停下來等待
  - 場上只有食材，沒有障礙物或敵人
  - 所有食材的移動速度相同，在隊伍中以固定間隔排列
  - 「吸」和「吐」只作用在龍所在那一層、隊伍最右邊（最靠近龍）的那一個食材
  - 每一層最多累積設定數量的食材（預設 5 個）。累積滿了就停止在該層產生新食材，直到該層有食材被吸走或被龍噴火燒掉
  - 最右邊的食材被吸走或燒掉後，該層後面的食材會往右遞補，並檢查該層食材數量是否低於上限；低於上限就產生新食材
- 鍋子：每一層的右邊各有一個鍋子
  - 每一鍋會列出 1～3 種禁止放入的食材，例如「不可以有人類、史萊姆」
  - 每一鍋要收集 2～5 個食材才算完成
  - 食材不用先烤，直接吸就可以。吸到的食材會立刻變成龍所在那一層右邊鍋子裡的食材
  - 每次吸到食材都會檢查是否為該鍋的禁止食材。吸到禁止食材時，該鍋已累積的食材數量會清空歸零，重新累積
- 勝敗條件：
  - 成功：累積完成的鍋數達到指定數量
  - 失敗：鍋子被清空的次數達到指定數量
  - 不限時間，沒有時間壓力
- 結束畫面：
  - 失敗：跳出失敗介面，有「重玩」和「回到標題」兩個選項
  - 成功：跳出成功介面，有「回到標題」選項

## 未定事項
- 一鍋完成後會怎樣（得分、換新的一鍋並重新決定禁止食材與需求數量）
- 每一鍋的禁止食材和需求數量怎麼決定（隨機 / 依關卡設計），是否顯示需求數量
- 「吸」「吐」字音辨識的做法（語音辨識套件 / 自行分析聲音特徵）
- 各種食材除了種類之外是否有差異（出現在哪幾層、出現機率）
- 食材的移動速度與間隔距離的數值
- 鏡頭是側面視角嗎（從側面看龍，龍頭朝左）
- 美術風格（低多邊形 / 寫實 / 卡通），模型自製還是使用免費素材
- 校正測的是環境噪音（大家都安靜），還是玩家 A 說一句話；三段音量的門檻怎麼從校正值算出來
- 玩家 B 的麥克風是否也要校正
- 音量要維持多久才算換層（避免聲音漸強或收尾時，經過中間音量造成龍誤換層）
- 麥克風以外的輔助操作要用什麼、負責哪些事（例如選單、暫停）
- 兩支麥克風的收音互相干擾怎麼處理
- 成功與失敗需要的指定數量是多少，是否依關卡不同
- 標題畫面的內容（開始遊戲、麥克風設定 / 校正等）
- 目標平台（Windows / Web），依效能測試與雙麥克風測試結果決定
- 範圍（必做 / 有時間再做）
